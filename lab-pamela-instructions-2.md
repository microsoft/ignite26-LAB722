## Agent model access and isolation

The old generated-code Sandboxes have no usable Azure identity and deny unrestricted egress. Full agent runtimes need a deliberately implemented model-call path; they cannot inherit the old profile unchanged.

The implemented model relay stays in the execution service. The Sandbox agent writes a root-only request file; the manager reads it using authenticated native execution, calls the allocated model using its managed identity, and writes the correlated response. The Sandbox needs no model key, Azure identity, run grant, HTTP model ingress, or permitted outbound model-gateway egress. Its default network policy remains Deny with Full inspection. Model and tool calls have bounded iteration and wall-time budgets.

Keep the lifecycle manager's Azure management identity outside the specialist Sandboxes. Distinguish the trusted agent runtime's model access from any untrusted Python subprocess; retain restricted subprocess identity, environment, filesystem, output, and time limits.

## User and service identity lesson

Use the existing validated Alice/Bob demo login and stable application customer map. A dropdown alone is not authentication. Two independently signed-in tabs or sessions may make the comparison easy, but the server determines ownership.

Explain the complete path in about two minutes:

1. The app authenticates the demo user and binds the research run to their customer.
2. Service identities authenticate backend components; the execution API checks its intended token audience and permitted caller.
3. A backend-issued, scoped capability binds tool execution to the authorized run and owner.
4. The execution manager selects isolated specialist Sandboxes and enforces access to their results and working data.

Toolbox is the managed tool boundary in this architecture, not automatic customer isolation. Application checks and run-bound capabilities enforce customer ownership. Label demo ownership **application-asserted** and validated backend callers **service-authenticated**. Do not claim Entra end-user delegation or token propagation that has not been proved.
